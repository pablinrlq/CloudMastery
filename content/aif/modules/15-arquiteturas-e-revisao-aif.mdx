## Comparações decisivas

| Necessidade | Escolha provável |
|---|---|
| consumir FMs por API com recursos de GenAI gerenciados | Amazon Bedrock |
| ciclo completo e customizado de ML | SageMaker AI |
| fatos privados, atuais e citáveis | RAG/Knowledge Bases |
| adaptar comportamento com exemplos | fine-tuning |
| busca por significado | embeddings + índice vetorial |
| fluxo determinístico e auditável | regras/Step Functions, não autonomia irrestrita |
| ação flexível com ferramentas | agente com limites e aprovação |

## Cenário 1: central de atendimento

Transcrições entram com PII mascarada. Um classificador roteia intenção; RAG recupera políticas autorizadas; Bedrock gera resposta com citações; Guardrails filtra tópicos; baixa confiança envia ao atendente. Métricas medem resolução, groundedness, segurança, latência e custo.

## Cenário 2: previsão de demanda

Dados históricos e promoções alimentam uma pipeline no SageMaker AI. O modelo gera previsão em lote. Monitoramento compara previsão com vendas reais e detecta drift. GenAI pode explicar resultados, mas não substitui o modelo preditivo.

## Cenário 3: agente financeiro

O agente pode consultar saldo, mas transferência exige autenticação reforçada, limite, confirmação e API idempotente. O modelo nunca recebe permissão administrativa. Todas as chamadas ficam auditáveis.

## Checklist final

Explique claramente tokens, embeddings, hallucination, RAG, fine-tuning, agentes, métricas e princípios responsáveis. Para cada arquitetura, localize dados sensíveis, fronteira de autorização, validação da saída e responsável pela decisão.

## Mais comparações que derrubam candidatos

| Dúvida | Diferença |
|---|---|
| Amazon Q Business × Knowledge Bases | Q Business é um assistente pronto para funcionários; Knowledge Bases é o bloco para você construir o seu RAG |
| Kendra × OpenSearch | Kendra é busca corporativa pronta com conectores; OpenSearch é motor de busca e vetores que você configura |
| Comprehend × LLM | Comprehend é barato e consistente para sentimento e entidades; LLM é flexível para tarefas abertas |
| Textract × LLM | Textract extrai dados de documentos com coordenadas; LLM interpreta e resume o texto extraído |
| A2I × Guardrails | A2I coloca humanos para revisar; Guardrails filtra automaticamente |
| Clarify × Model Monitor | Clarify mede viés e explica; Model Monitor acompanha a produção (usando o Clarify para viés) |
| CloudTrail × invocation logging | Quem chamou a API × o conteúdo do prompt e da resposta |
| Fine-tuning × pré-treinamento contínuo | Dados rotulados × texto do domínio sem rótulo |

## Revisão final em 15 itens

1. IA ⊃ ML ⊃ deep learning; IA generativa cria conteúdo.
2. Supervisionado usa rótulos; não supervisionado agrupa; reforço usa recompensas.
3. Overfitting: ótimo no treino, ruim em dados novos.
4. Precisão evita falso positivo; recall evita falso negativo.
5. Tokens definem custo e limite de contexto.
6. Temperature baixa = consistência; max tokens corta a resposta.
7. Embeddings + banco vetorial = busca por significado.
8. RAG para conhecimento atualizado e citável; fine-tuning para comportamento.
9. Prompt → RAG → fine-tuning → pré-treinamento: custo crescente.
10. Agentes precisam de menor privilégio, limites e confirmação.
11. ROUGE para resumo, BLEU para tradução, BERTScore para semântica.
12. Guardrails, Clarify, A2I e Model Cards para IA responsável.
13. Bedrock não treina modelos base com seus dados.
14. PrivateLink, KMS, IAM, CloudTrail e invocation logging protegem e auditam.
15. Artifact, Audit Manager e Config apoiam a conformidade.
