## Amazon Bedrock

Amazon Bedrock fornece acesso gerenciado a foundation models por API e recursos para construir aplicações generativas sem administrar a infraestrutura de treinamento/inferência subjacente. A plataforma inclui model evaluation, Knowledge Bases para RAG, Agents, Guardrails e opções de customização, conforme modelo e Região.

Bedrock não substitui SageMaker AI. Bedrock acelera aplicações com FMs gerenciados; SageMaker AI oferece controle amplo sobre o ciclo de ML, treinamento, notebooks, pipelines e endpoints de modelos próprios.

## Amazon Nova

Amazon Nova é uma família de modelos da AWS com capacidades que variam por modalidade e perfil de custo/performance. A decisão continua orientada a benchmark: “modelo da AWS” não significa automaticamente melhor para toda tarefa.

## Assistentes e ferramentas

- **Amazon Q:** experiências de assistência para negócios e desenvolvimento, integradas a contextos e permissões.
- **Amazon Quick:** experiências assistidas por IA para trabalho e dados, conforme o produto disponível.
- **Kiro:** ambiente de desenvolvimento orientado por especificações e assistência de IA.
- **Strands Agents:** SDK aberto para construir agentes orientados a modelos e ferramentas.
- **Bedrock AgentCore:** componentes para operar agentes com identidade, runtime, observabilidade e outras capacidades gerenciadas.
- **AWS Transform:** experiências de transformação/modernização assistidas por IA.

Para o exame, reconheça a categoria e o problema resolvido. Para produção, confirme disponibilidade regional, limites e controles atuais antes de desenhar a solução.

## Cenário

Uma empresa quer um assistente interno sobre manuais. Bedrock fornece o FM, Knowledge Bases implementa recuperação, Guardrails filtra conteúdo e IAM controla acesso. Logs e avaliações medem groundedness. Se o objetivo fosse treinar um modelo preditivo proprietário com pipeline completo, SageMaker AI seria mais adequado.

## Mapa de recursos do Amazon Bedrock

| Recurso | O que resolve |
|---|---|
| Catálogo de modelos | Modelos de fundação de vários fornecedores (Amazon Nova, Anthropic, Meta, Mistral, Cohere e outros) por uma API |
| Converse API | Mesmo formato de requisição para conversas e uso de ferramentas entre modelos |
| Knowledge Bases | RAG gerenciado: ingestão, chunking, embeddings, banco vetorial e citações |
| Agents | Orquestração de tarefas com action groups e bases de conhecimento |
| Guardrails | Filtros de conteúdo, tópicos negados, PII, fundamentação contextual |
| Model Evaluation | Avaliação automática, com LLM como juiz, ou humana |
| Customização | Fine-tuning, pré-treinamento contínuo e destilação |
| Prompt Management e Flows | Versionar prompts e montar fluxos visuais |
| Inferência em lote e Provisioned Throughput | Reduzir custo em volume ou garantir capacidade |
| Model invocation logging | Registrar prompts e respostas para auditoria |

## Bedrock, SageMaker AI ou serviço pronto?

| Se o cenário pede… | Escolha |
|---|---|
| Gerar texto, resumir, conversar com um modelo de fundação por API, sem gerenciar servidores | Amazon Bedrock |
| Treinar, ajustar e hospedar modelos próprios com controle total do ciclo | Amazon SageMaker AI |
| Implantar um modelo open source pré-treinado em um endpoint próprio com poucos cliques | SageMaker JumpStart |
| Uma tarefa específica sem treinar nada (OCR, tradução, sentimento) | Serviço de IA pronto |

## Pegadinhas

- **Bedrock não usa seus prompts para treinar os modelos base**, nem os compartilha com os fornecedores.
- **"Analisar imagens" é Rekognition; "gerar imagens" é um modelo no Bedrock** (como o Nova Canvas).
- **Textract extrai; Comprehend entende.** Para "extrair campos de um formulário e depois detectar o sentimento", usam-se os dois.
