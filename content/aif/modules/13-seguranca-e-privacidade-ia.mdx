## Modelo de ameaça

Mapeie dados de treino, documentos RAG, prompts, outputs, embeddings, logs, modelos e ferramentas. Para cada ativo, defina quem pode ler, alterar ou executar. Dados sensíveis podem aparecer tanto na entrada quanto na saída e em telemetria aparentemente inofensiva.

## Controles AWS

IAM aplica least privilege; KMS protege dados em repouso; TLS protege trânsito; VPC endpoints reduzem exposição à internet; CloudTrail registra chamadas; CloudWatch monitora operação; Macie ajuda a descobrir dados sensíveis em S3. Secrets Manager armazena segredos rotacionáveis. A escolha depende do fluxo real de dados.

## Ameaças generativas

- prompt injection direta ou em documentos recuperados;
- vazamento de system prompt ou dados entre usuários;
- saída insegura executada como código/SQL/HTML;
- tool use com privilégios excessivos;
- poisoning de fontes ou datasets;
- denial of wallet por prompts caros e loops;
- model inversion/membership inference em contextos específicos.

## Arquitetura

Autentique o usuário antes da recuperação, aplique filtros por documento, minimize contexto, remova PII, valide a saída e autorize cada ferramenta fora do modelo. Rate limits e budgets limitam abuso. Guardrails complementam, mas não substituem IAM e validação determinística.

## Cenário

Um chatbot de RH usa políticas por país. O usuário só recupera documentos permitidos para sua região e função. Logs mascaram identificadores, chaves ficam no Secrets Manager e o modelo não pode chamar sistemas de folha. Solicitações de alteração viram tickets revisados por humanos.

## O que o Bedrock garante e o que fica com você

| A AWS cuida de | Você cuida de |
|---|---|
| Infraestrutura, hospedagem e isolamento dos modelos | Quem pode invocar quais modelos (IAM) |
| Não usar seus prompts e respostas para treinar os modelos base | Quais dados entram nos prompts e no RAG |
| Não compartilhar seus dados com os fornecedores dos modelos | Configurar guardrails, filtros e validação da saída |
| Criptografia em trânsito e em repouso | Escolher chaves KMS gerenciadas pelo cliente quando exigido |
| Disponibilidade do serviço na Região | Registrar invocações, revisar logs e responder a incidentes |

## Controles específicos para IA generativa

- **Rede privada:** VPC endpoint de interface (PrivateLink) para o Bedrock, sem passar pela internet.
- **Auditoria de API:** CloudTrail registra quem chamou qual API e quando.
- **Conteúdo das invocações:** model invocation logging grava prompts e respostas no CloudWatch Logs ou no S3. Proteja esses logs, porque eles podem conter dados sensíveis.
- **Dados de treino e RAG:** Macie encontra PII no S3 antes da ingestão; KMS e políticas de bucket restringem o acesso.
- **Menor privilégio:** políticas IAM limitando `bedrock:InvokeModel` aos modelos aprovados.

## Generative AI Security Scoping Matrix

| Escopo | O que a empresa usa | Exemplo |
|---|---|---|
| 1. Aplicação de consumo | App público de IA | Usar um chatbot público no navegador |
| 2. Aplicação corporativa | SaaS com recursos de IA | Ferramenta de e-mail com resumo automático |
| 3. Modelo pré-treinado | Modelo de terceiros via API | Aplicação própria sobre o Bedrock |
| 4. Modelo ajustado | Modelo customizado com seus dados | Fine-tuning no Bedrock |
| 5. Modelo próprio | Treinado do zero pela empresa | Pré-treinamento no SageMaker AI |

Quanto maior o escopo, mais controles ficam com a empresa: dados de treino, avaliação, hospedagem e resposta a incidentes.

## Pegadinhas

- **CloudTrail não guarda o texto dos prompts.** Para isso existe o model invocation logging.
- **Guardrails não substituem IAM.** Um usuário sem permissão não deve sequer conseguir chamar o modelo.
- **Dados pessoais nos logs também são dados pessoais:** mascare, restrinja e defina retenção.
